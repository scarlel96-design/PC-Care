# 보안 삭제·장치 Purge 감사

코드의 `PathSafetyGuard`는 문자열 경로와 직접 재분석 항목을 검사하지만 부모 디렉터리 재분석, 검사 뒤 교체, 파일 식별자/하드링크 문제는 별도 검증이 필요하다. 시뮬레이션과 dry-run은 실제 매체의 잔존 데이터 확인을 대체하지 않는다.

파일 삭제 경로의 다음 설계 게이트는 파일 핸들 기반 대상 동일성 확인, 각 부모의 재분석 방어, 하드링크 수·공유 모드·경합 차단, 작업 전후 식별자 기록, 실패 시 보수적 중단이다. SSD/복제·스냅샷·클라우드 동기화에는 개별 파일 덮어쓰기만으로 회수 불가능성을 확정할 수 없다. 장치 전체 Purge는 장치/펌웨어 명령 지원, 명령 완료 증거, 독립 샘플링/문서화를 별도 요구한다.

판정: 자동 테스트 존재, 실매체 검증 미확인. 상용/정부 포렌식 대비 복원 불가 비율은 산정하지 않는다. 현행 기준은 [NIST SP 800-88 Rev.2](https://csrc.nist.gov/pubs/sp/800/88/r2/final)이다.

## 위협·데이터 손실·승인 조건

공격자는 선택 후 대상 경로의 부모를 정션으로 교체하거나, 동일 내용의 하드링크/스냅샷/동기화 사본을 남길 수 있다. 사용자가 폴더를 잘못 선택할 수도 있다. 경로 문자열 확인만으로 이 상황의 실제 대상 동일성을 입증하지 못한다. 잘못된 대상 파괴와 삭제 실패를 모두 실패로 보고해야 한다.

생산 승인에는 테스트 전용 볼륨의 허용/차단 경로 행렬, 공격적인 재분석·하드링크·경합 fixture, 파일 핸들·식별자 재확인, 대상 규모/매체별 실측, 작업 로그의 제품 문구 일치가 필요하다. 장치 Purge는 모델·펌웨어·명령 지원별 독립 검증과 증거 보존을 추가 요구한다. SSD·가상/클라우드 저장소에는 한 기술의 성공을 다른 매체의 보증으로 확장하지 않는다.
