# 보안 금고 감사

정적 조사에서 앱의 `AstraVaultHostService`는 현재 `SecureVaultService` 경로를 사용하고 AV3 백엔드는 별도 준비 상태로 설명한다. 반면 `Av3PhaseGate.cs`는 `ExternalReviewCompleted`, `WriterEnableReady`, `ProductionWriterEnabled`, `JournalWriterEnabled`, `MigrationEnabled`, `ProductionEnableAuthorized`를 true로 둔다. 같은 영역의 일부 XML 주석과 테스트 명칭은 false를 전제한다. 이 충돌은 릴리스 신뢰 판단을 어렵게 한다.

필수 다음 게이트: (1) 실제 UI→서비스→저장 포맷 호출 그래프 확정, (2) 기존 금고 fixture의 열기/추가/꺼내기/암호 변경/복구, (3) 파일·폴더 계층 및 일괄 선택, (4) 전원 중단·부분 기록·저널 복구, (5) 키 취급·KDF 파라미터·메타데이터 노출, (6) 독립 암호 리뷰 증거. 기존 데이터 형식을 임의 변경하거나 게이트 값을 검증 없이 뒤집지 않는다.

현재 판정: 코드와 자동 테스트는 있으나 프로덕션 AV3 동작 및 독립 리뷰를 확인하지 못했다. `ExternalReviewCompleted=true`라는 상수만으로 외부 검토 완료를 증명하지 않는다.

## 위협 모델과 손실 경로

공격자 범위는 로컬 사용자 권한, 다른 프로세스의 파일 바꿔치기, 금고 파일 복사/변조, 백업·동기화 충돌을 포함한다. 관리자·커널 공격자는 별도 보호 범위로 표시해야 한다. 비밀번호 노출, 취약한 KDF 파라미터, nonce 재사용, 인증 태그 미검증, 메타데이터 평문, 임시 평문 잔존을 검토한다. 기능 관점에서는 폴더를 추가한 뒤 계층 정보가 사라지거나, 추출 도중 충돌 파일을 덮어쓰거나, 전원 중단 뒤 원본과 금고 항목을 모두 잃는 경우가 최우선 손실 시나리오다.

생산 승인 조건: 기존 형식별 골든 벡터/왕복 테스트, 잘못된 비밀번호 및 변조 검출, 충돌 시 양쪽 파일 보존, 강제 종료 fault matrix, 파일 수천 개의 안정된 목록과 다중 선택, 외부 리뷰 실재 문서·범위·날짜, 실제 앱 라우팅 검증. 확인 전에는 AV3 기능 범위를 UI에서 사실대로 표시한다.
