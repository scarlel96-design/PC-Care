## 선택 및 실행 경로

A를 선택했다. WO-05 트랜잭션과 파일 경계를 재사용했다.
앱은 설치된 도우미의 고정 경로를 검증한 뒤 UAC를 요청한다.
도우미는 ProgramData/PC-Care/UpdateTransactions/bootstrap-GUID에 실행 스냅샷을 만든다.
스냅샷은 EXE, 도우미 DLL, 엔진 DLL, deps.json, runtimeconfig.json을 포함한다.
도우미는 스냅샷 프로세스를 시작한 뒤 종료한다.
스냅샷은 부모 도우미와 앱의 종료를 기다린다.
스냅샷은 설치 디렉터리의 기록된 ID를 다시 확인한 뒤 트랜잭션을 실행한다.
실행 위치에서 설치 루트를 추론하지 않는다.

binding.json은 설치 ID, 스냅샷 ID, 파일 ID, 길이, 해시, 명령과 PID를 기록한다.
읽기는 중복 속성, 알 수 없는 속성, 누락된 필드, 외부 경로를 거부한다.
관리자와 SYSTEM만 쓸 수 있는 경계에서 실행 파일 인증을 다시 검사한다.
JSON 런타임 파일은 인증된 원본 스냅샷의 해시와 ID에 바인딩한다.
실행 명령은 --apply, --recover, 내부 bootstrap 명령으로 제한한다.
새 설치 도우미가 손상되면 인증된 이전 스냅샷에서 복구를 시작할 수 있다.
outcome 파일은 결과 단계, 코드, 종료 코드와 트랜잭션 ID를 기록한다.

## 남은 조건

실제 인증된 도우미의 자체 갱신은 전용 VM에서 실행해야 한다.
기존 WO-05 도우미에는 새 부트스트랩이 없다.
최초 전환에는 검토된 서명 설치기 또는 별도 전환 패키지가 필요하다.
이 작업은 기존 WO-05 설치본에서 직접 전환 성공을 증명하지 않았다.
Program Files 밖의 설치본과 사용자 쓰기 가능한 설치본은 거부한다.
TrustedInstaller 소유의 다른 ACL 배치는 별도 검토가 필요하다.
스냅샷은 복구용으로 보존한다. 자동 정리와 저장 공간 한도는 미구현이다.
PID 재사용은 대기 실패를 발생시킬 수 있다. 시작 시간 바인딩은 후속 항목이다.
런타임 목록은 현재 .NET 10 의존성에 한정된다.
향후 추가 의존성을 패키지와 고정 목록에 함께 반영해야 한다.
공식 키 회전과 이전 스냅샷 신뢰 정책은 생산 서명 인프라에 종속된다.
