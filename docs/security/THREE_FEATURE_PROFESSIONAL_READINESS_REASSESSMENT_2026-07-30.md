# PCCare 보안 3기능 최종 심층 재점검

- **작성일:** 2026-07-30
- **대상:** 보안 금고(Astra/Secure Vault), 보안 삭제(File Clear), 장치 PURGE(NVMe)
- **판정 원칙:** 코드에 존재하는 기능, 자동 테스트로 확인한 기능, 실제 장비와 독립 평가로 입증한 기능을 같은 것으로 취급하지 않는다.
- **범위 밖:** 개발자 Authenticode 인증서의 구매·발급. 이 문서는 이를 품질 점수에 감점으로 넣지 않는다.

## 1. 결론 요약

현재 세 기능은 일반 PC 유틸리티 수준을 넘는 안전장치와 암호화·사전검증 구조를 갖췄다. 그러나 최고급 전문/정부 조달 제품과 동급이라고 발표할 근거는 아직 없다. 특히 장치 PURGE와 SSD/NVMe 파일 삭제는 **실제 하드웨어·펌웨어·포렌식 환경에서의 독립 검증**이 없으므로 “복구 불가” 또는 “정부 대응”을 주장하면 안 된다.

| 기능 | 제품 코드·자동화 성숙도 | 운영·독립 검증 성숙도 | 전문 제품 대비의 정직한 판정 |
|---|---:|---:|---|
| 보안 금고 | 70/100 | 45/100 | 강한 개인용 로컬 금고 후보. 고급 상용 암호화 금고와 비교 가능한 기반은 있으나, 포맷의 `-lab` 상태·실매체 내구성·외부 보안감사가 미완료다. |
| 보안 삭제 | HDD 논리 Clear 65/100, SSD/NVMe 논리 Clear 40/100 | 30/100 | 안전한 파일 단위 정리 도구로는 양호하다. 전문 매체 소거 제품의 장치/펌웨어 삭제, 독립 검증, 인증서 발급 수준은 아니다. |
| 장치 PURGE | 70/100 | 35/100 | NVMe 한정 WinPE 실행 경로와 다중 안전 게이트는 갖췄다. 지원 매체 폭·실장비 검증·운영 증명 체계가 없어 전문 Drive Eraser급으로 분류할 수 없다. |

점수는 마케팅 점수가 아니라 다음 빌드의 우선순위를 정하기 위한 내부 척도다. 운영·독립 검증이 85가 되기 전에는 85% 달성 또는 포렌식 복구 불가라고 발표하지 않는다.

## 3. 기준선과 비교 방법

NIST는 매체 소거를 Clear, Purge, Destroy로 구분하며, 데이터의 기밀도와 매체 특성에 맞춰 결정하도록 한다. 최신 판은 SP 800-88 Rev.2이며 Rev.1은 2025년에 대체되었다. PCCare의 파일 단위 기능은 이 분류에서 **Clear**로만 표기한다. [NIST SP 800-88](https://csrc.nist.gov/pubs/sp/800/88/r1/final)

Windows의 `IOCTL_STORAGE_REINITIALIZE_MEDIA`는 소거를 장치에 위임하지만, Microsoft는 호출 완료 후 성공적인 삭제 또는 복구 가능성에 대한 보증이 없다고 명시한다. 볼륨 잠금도 호출 전 요구한다. [Microsoft IOCTL 문서](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-ntddstor-ioctl_storage_reinitialize_media)

비교 대상의 예로 Blancco는 다양한 HDD/SSD/NVMe, 표준별 프로파일, 대량 처리, 검증, 인증서 및 제3자 인증을 공개적으로 제공한다고 설명한다. 이는 공급사 주장과 공개 인증의 비교 기준이며, PCCare가 동일 인증을 보유한다는 뜻은 아니다. [Blancco Drive Eraser](https://blancco.com/products/drive-eraser/), [공개 인증 목록](https://blancco.com/about-us/our-certifications/)

금고의 KDF는 RFC 9106의 Argon2id와 비교했다. RFC는 메모리 하드 설계와 권장 파라미터를 설명하고, OWASP는 최소 19 MiB/2회/병렬 1의 Argon2id 기준을 제시한다. PCCare 신규 Strong 프로필은 256 MiB·3회·병렬 4라서 최소선보다 높지만, 이것만으로 전체 금고의 안전성이나 외부 감사를 대체하지 않는다. [RFC 9106](https://www.rfc-editor.org/rfc/rfc9106.html), [OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)

## 4. 기능별 엄격 판정

### 4.1 보안 금고

**확인된 강점**

- 신규 v5 Lab 경로는 Argon2id, HKDF 분리 키, AES-GCM 키 래핑, XChaCha20-Poly1305 청크 AEAD, AAD, 파서 한계 검사, 키 메모리 소거를 구현한다.
- 비밀번호 정책·실패 속도 제한·복구 코드·자동 잠금·감사 체인·콘텐츠 해시 및 잠금 상태 컨테이너 점검을 제공한다.
- 폴더를 구조적으로 표시·다중 선택 내보내기하며, 원본 보안 삭제 실패 시 성공으로 위장하지 않고 원본 잔존 가능성을 알린다.
- 공격 시뮬레이션에서 잘못된 비밀번호, 변조한 매니페스트/키 봉투, 손상 샤드, 복구 속도 제한, 원래 폴더 복원이 통과했다.

**전문 제품과의 결정적 격차**

- 현 포맷과 코드가 `spd-vault-v5-lab`/SecurityLab이라는 이름과 제품 플래그를 사용한다. 이미 제품 경로에서 활성화될 수 있어도, 문서상 “Lab/실험”과 실제 배포 상태의 경계가 불명확하다. 이 상태는 전문 제품의 릴리즈 거버넌스로 인정할 수 없다.
- AV3의 프로덕션 writer·외부 앵커·외부 보안 검토는 별도 문서에서 여전히 NO-GO/미완료로 남아 있다. AV3 설계 패키지가 존재한다는 사실을 현 금고의 외부 감사 완료로 해석하면 안 된다.
- 독립 코드 감사, 암호 라이브러리 공급망 SBOM/취약점 감시, 실제 사용자 디스크의 전원 차단·공간 부족·동시 접근 내구성 시험, 장기 호환성/복구 SLA가 없다.
- 앱 메모리·운영체제·관리자/커널 공격자에 대한 완전한 비밀성 보장은 사용자 모드 금고만으로 불가능하다. TPM/Windows Hello/하드웨어 키와의 선택적 키 보호, 위협 모델 문서가 필요하다.

**판정:** 강한 개인용 로컬 금고 후보. 현재 구현은 “암호화 사용” 단계보다 낫지만, 제3자 감사와 정식 포맷 수명주기 없이 전문 암호화 컨테이너로 배포하면 안 된다.

### 4.2 보안 삭제

**확인된 강점**

- 사전 점검이 보호 경로, 재분석 지점/심볼릭 링크, 순회 실패, 잠긴 파일, 하드링크, ADS, 특수 파일 속성, VSS 존재, BitLocker 상태 및 권한을 확인하고 안전하지 않으면 차단한다.
- HDD/NTFS 계열에는 수준별 1·3·7회 쓰기, 쓰기 완료/표본 검증, 이름 난수화, truncate 및 삭제를 적용한다.
- SSD/NVMe에서는 다중 파일 Clear와 TRIM을 수행하되 장치 crypto erase가 아니며 물리 삭제를 보장하지 않는다는 제한을 코드·UI 정책에 명시한다.
- 파일 단위 인증 저항 수준을 0으로 고정하여 허위 ‘Level 5/6’ 또는 인증 완료 표기를 막는다.

**전문 제품과의 결정적 격차**

- SSD/NVMe의 웨어 레벨링·오버프로비저닝·리맵 영역, USB 브리지, 펌웨어 특성을 파일 덮어쓰기로 검증할 수 없다. 이는 제품 결함이라기보다 파일 수준 도구의 본질적 한계다.
- VSS·백업·클라우드 동기화·다른 장치의 사본은 감지/고지 일부만 가능하며, 전체 사본 인벤토리나 정책 기반 삭제 워크플로가 없다.
- 독립 포렌식 복구 시험, 매체별 검증 도구, 고객/자산/작업자 연계형 서명 인증서, 대량 처리·원격 관리가 없다.
- 삭제 성공의 감사 기록은 있지만, 파일 시스템/펌웨어가 기록한 각 실제 쓰기와 비가시 영역까지 증명하는 증적은 아니다.

**판정:** HDD 등의 파일 단위 **논리 Clear**로는 보수적이고 정직한 구현이다. SSD/NVMe와 전문 매체 소거 요구에는 장치 PURGE 경로로 승격하거나 물리 파기를 선택해야 하며, 현재 보안 삭제 자체를 전문 포렌식 대응 도구로 홍보하면 안 된다.

### 4.3 장치 PURGE

**확인된 강점**

- 일반 Windows에서 장치 명령을 거부하고 WinPE와 NVMe만 허용한다.
- 디스크 번호만 믿지 않고 고유 ID·시리얼·크기·버스 타입을 재확인하며, 5분 이내의 읽기 전용 증적과 NVMe Identify, Command Effects, Sanitize Status 교차검증을 요구한다.
- 부팅/시스템 디스크, 확인 문구 오류, 일회용 승인 누락, 지원되지 않는 방식, 볼륨 잠금 실패는 전송 전에 차단한다.
- Block Erase/Crypto Erase만 허용하고 취소 후 잠금을 성급히 풀지 않으며, 장치가 보고한 진행/실패/완료를 구분한다.

**전문 제품과의 결정적 격차**

- 실제 WinPE NVMe 장비에서의 성공·실패·전원 차단·재부팅·시간초과·열/SMART 이상·다른 펌웨어 조합 시험이 없다. 현재 36개 시험은 가짜 전송 계층 기반이다.
- 지원 범위는 NVMe Crypto/Block Erase뿐이다. SATA/ATA, SAS/SCSI, USB 브리지, eMMC/UFS, Apple/T2 등은 지원하지 않는다.
- Windows 스토리지 API/OS 버전/드라이버/펌웨어 조합의 호환성 매트릭스 및 안전한 fallback이 없다. NVMe Sanitize 관련 Windows 지원 제약은 공식 StorNVMe 문서에 따라 매체·OS별로 확인해야 한다. [Microsoft StorNVMe 지원표](https://learn.microsoft.com/en-us/windows-hardware/drivers/storage/stornvme-command-set-support)
- 컨트롤러 완료 상태는 독립적인 물리 복구 불가 증명이 아니다. 전·후 상태, 장치 로그, 자산 식별, 작업자, 검증 방법을 묶은 장치별 소거 인증서도 아직 없다.

**판정:** 위험한 명령을 함부로 내리지 않도록 설계한 NVMe 전용 후보 실행기다. 전문 Drive Eraser의 기능 폭·현장 검증·인증서 체계와는 아직 큰 차이가 있다.

| P0 | 장치 PURGE | 명령 제출 전/후의 변조 방지 실행 증적과 사람이 검토 가능한 실패 복구 절차를 설계한다. | 대상 지문, 승인, 시간, 방법, 상태 로그 해시, 결과 및 한계를 포함한 서명/검증 가능한 보고서. |

## 6. 85% 목표를 위한 단계별 로드맵

1. **신뢰성 기반:** P0 전부 완료, 전체 회귀를 재현 가능하게 만들고 외부/실매체 미검증 항목을 제품에서 명확히 숨긴다.
2. **금고 85:** 정식 포맷 수명주기, 프로덕션 내구성 시험, 독립 암호 검토, 공격 표면/키 수명/복구 정책 문서화, 호환성 시험을 완료한다.
3. **보안 삭제 85(정직한 범위):** 파일 Clear 제품으로서의 85다. 매체별 정책, 완전한 사본 위험 고지, 감사·오류 복구·대량 처리·관리자 정책을 완성한다. SSD의 물리 삭제 주장은 하지 않는다.
4. **장치 PURGE 85:** 실제 NVMe 매트릭스, WinPE 이미지 관리, 지원/차단 목록, 명령 결과 증적, 장애 처리와 독립 검증 시험을 완료한다. 미지원 장치는 강제 실행하지 않고 전문 소거 또는 파기 절차로 안내한다.
5. **그 이후:** SATA/SAS/USB/eMMC 등은 각각의 공식 명령·검증 절차와 실장비 시험이 완료된 경우에만 별도 모듈로 추가한다. 한 경로를 다른 매체에 재사용하지 않는다.
