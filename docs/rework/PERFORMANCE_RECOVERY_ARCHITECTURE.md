# 성능·복구 구조 초안

진단 파이프라인은 `규칙 식별→관찰 수집→근거 평가→수정 제안→사용자 범위 확인→적용→결과/복구 기록`으로 분리한다. 개별 규칙은 입력 자료, 판정 근거, 오탐 예외, 적용 전 조건, 적용 후 확인, 복구 동작을 선언해야 한다. 시스템 케어의 대형 서비스는 규칙 카탈로그와 실행 조정자로 분할할 후보이다.

동시 실행은 CPU/디스크/네트워크 비용별 큐와 취소 토큰으로 제한한다. UI는 실제 완료한 단위만 퍼센트에 반영하고 단계와 전체 진행률을 단일 타임라인으로 보여준다. 성능 측정은 동일 장치의 반복 기준선, 기동 시간, 메모리 피크, UI 프레임, 스캔 처리량, 오탐률로 기록한다. 측정하지 않은 향상은 주장하지 않는다.

변경 작업은 사전 스냅샷(가능한 범위), 작업 저널, 성공 확인, 복구 핸들을 남긴다. 삭제·암호화·업데이트는 임시 파일 작성→검증→원자적 교체/커밋→정리 순서를 목표로 한다. 실패한 단계의 파일과 원본이 어느 위치에 있는지 기록해야 한다.

| 병목 유형 | 수집 증거 | 분석 | 복구 후보 | 안전 장치/측정 |
|---|---|---|---|---|
| 시작 지연 | 기동 구간 시간, 자동 시작 항목, 디스크 대기 | 동일 부팅 3회 중앙값 및 후보 상관 | 시작 항목 정리 제안 | 기본 비활성 금지, 이전 상태 기록, 기동 시간 재측정 |
| 저장장치 포화 | 활성 시간·대기열·여유 공간·I/O 주체 | 지속 부하와 일시 스파이크 분리 | 임시 파일·대형 캐시 검토 | 경로 허용 목록, 격리, 여유 공간/응답 시간 비교 |
| 메모리 압박 | 커밋/가용 메모리·하드 폴트·프로세스 | 재현 구간 상관 | 원인 앱·시작 항목 설명 | 프로세스 강제 종료 자동화 금지, 재현 전후 측정 |
| CPU/GPU 끊김 | 프레임 시간·사용률·열/전력 상태 | 프레임 지연과 자원 포화 시간 정렬 | 드라이버/전원 설정 점검 | 드라이버 교체 별도 동의, 프레임 분포 비교 |
| 네트워크·업데이트 | 실패 이벤트·연결 대기·재시도 | 원인 구간 추적 | 업데이트 상태 복구 | 다운로드 무결성, 재시도 상한, 재시작 완료 확인 |

ETW 기반 수집은 비용과 개인정보 범위를 통제하는 별도 구현 단계다. 현재 코드에 위 증거를 모두 수집하는 파이프라인이 있다고 확인하지 않았다. 성능 회복 수치는 절대 점수보다 동일 장치 동일 작업의 전후 분포와 신뢰구간으로 보고한다.
