# PCCare 보안 기능 4축 재계산 (2026-08-09)

## 판정

이번 재계산은 `SECURITY_MATURITY_SCORING_GATE.md`의 2026-08-09 규칙을 적용한다. 즉, 구현·자동화·실제 운영·독립 검증의 **각각**이 70 이상이어야만 "70% 완료"다. 참고용 가중 평균이 70을 넘더라도 어느 한 축이 미달이면 완료로 표기하지 않는다.

## 이번 실행으로 추가된 검증 가능한 변화

- 보안 삭제 Dry Run이 다중 대상 중 하나의 스냅샷 생성 실패를 개별 차단으로 남기고, 안전한 다른 대상의 계획을 계속 만들도록 변경했다.
- 재분석 지점 심볼릭 링크 회귀는 외부 대상으로만 만들고 명시적으로 제거하도록 보정했다. 테스트 정리 코드가 링크를 재귀 순회하지 않는다.
- 보안 삭제 감사 키·감사 로그·보고서는 하나의 감사 저장소로 묶였고, 서비스 생성 시 명시적 격리 저장소를 주입할 수 있다. 기본 제품 경로는 `%LocalAppData%\PC-Care\secure_delete`다.
- `scripts/diagnostics/run-security-readiness-gate.ps1`는 파괴 명령 없이 자동 테스트, 실행 로그, TRX, 호스트 정보와 선택 증거 파일의 SHA-256을 묶는다. 외부 증거의 존재·해시를 기록할 뿐 그것을 독립 검증으로 자동 승인하지 않는다.
- `scripts/diagnostics/new-security-operation-evidence.ps1`는 실제 운영 결과를 나중에 수집할 때 대상 지문·시나리오·운영자 식별자 해시·복수 전후 증거 파일 해시를 한 묶음으로 고정한다. 이 스크립트도 저장장치 명령을 실행하거나 독립 검증을 승인하지 않는다.
- PURGE 전송 API가 예외를 반환하면 `NotAttempted`와 `SubmissionUncertain`을 분리해 기록한다. 후자는 컨트롤러가 명령을 받지 않았다고 가정하지 않으며, 장치 재사용 전 WinPE 상태 확인을 요구한다.
- 격리된 로컬 NTFS에서 금고 import·원본 봉인·export와 파일 Clear를 실제로 실행했다. 제품 어셈블리를 로드하지 않는 PowerShell XML/해시 검증기가 TRX 3건을 교차 확인했다. 이는 별도 프로세스 검증이며 외부 제3자 검증은 아니다.
- 독립된 두 번째 테스트 프로세스와 새 임시 루트에서 위 실제 파일시스템 시나리오를 다시 실행해 3/3을 재현했다. 같은 PowerShell 검토기는 소스 경계 9개와 TRX 결과 1개, 총 10/10을 통과시켰다.

## 엄격한 점수

숫자는 기능의 마케팅 등급이 아니라, 현재 저장소 안에서 재현한 증거만 반영한 상한이다. 실제 디스크를 지우지 않았고 제3자가 실행·검토하지 않았으므로 마지막 두 축은 0이다.

| 기능 | 구현 | 자동화 | 실제 운영 | 독립 검증 | 70% 판정 |
|---|---:|---:|---:|---:|---|
| 보안 금고 | 70 | 68 | 12 | 0 | 미달 |
| 보안 삭제 (파일 Clear) | 72 | 70 | 10 | 0 | 미달 |
| 장치 PURGE (WinPE NVMe 한정) | 74 | 72 | 0 | 0 | 미달 |

### 점수 근거와 상한

- **구현:** 금고는 암호문·헤더·KDF 경계 시험을 통과했고, 보안 삭제는 파일 ID/구조 지문 재확인과 fail-closed 경로를 갖췄다. PURGE는 WinPE·대상 지문·승인·잠금·상태 증적을 강제한다. 다만 금고의 포맷 배포 거버넌스와 PURGE의 실제 드라이버/펌웨어 호환성은 완료되지 않았다.
- **자동화:** 재현 가능한 스크립트와 47개 집중 회귀, 24개 장기 공격 시뮬레이션은 존재한다. 하드웨어·전원 중단·독립 재현은 자동화 범위에 넣지 않았다.
- **실제 운영:** 격리된 로컬 NTFS에서 금고 원본 봉인·내보내기와 파일 Clear 3건을 실행해 금고 12, 보안 삭제 10의 제한적 운영 증거를 추가했다. 별도 희생 HDD/SSD/NVMe, WinPE 부팅, 원시 상태 로그, 재부팅/전원 중단/시간초과 기록은 아직 없으며 장치 PURGE는 0이다.
- **독립 검증:** PCCare 어셈블리를 로드하지 않는 별도 PowerShell 프로세스가 결과 TRX와 SHA-256을 확인했지만, 코드 작성자와 분리된 재현자나 외부 포렌식 복구 시도는 아니다. 따라서 엄격한 독립 검증은 세 기능 모두 0이다.

## 70%에 도달하기 위한 남은 증거 게이트

1. 보안 금고: 별도 머신에서 신규 컨테이너 생성·대용량 폴더 import/export·복구 코드·전원 중단/디스크 부족/동시 접근을 실행하고, 제3자가 암호문 변조·복구 테스트를 재현해야 한다.
2. 보안 삭제: 격리된 HDD와 SSD/NVMe 각각에서 파일 Clear의 성공·잠금 실패·경로 교체·VSS/백업 고지 결과를 수집해야 한다. SSD/NVMe 파일 Clear는 이 증거가 있어도 파일 수준 Clear로만 표기한다.
3. 장치 PURGE: 사용 중인 시스템 디스크가 아닌 전용 NVMe를 WinPE에서 대상으로 지정해 지원/차단·성공·실패·시간초과·중단 시나리오와 명령 전후 원시 상태 로그를 수집해야 한다. 실제 컨트롤러 완료는 그 자체로 복구 불가 증명이 아니다.
4. 독립 검증: 위 증거 묶음과 소스 revision을 제3자가 받아 독립 환경에서 재실행하고, 서명된/식별 가능한 결과 보고서를 남겨야 한다.

이 네 단계가 완료되기 전에는 네 축 각각 70 또는 정부·전문 포렌식 복구 불가라는 표현을 사용하지 않는다.
